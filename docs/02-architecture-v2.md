## 0. 先看结论：今晚试过的四个三模态变体，全部平在 RGB 基线上

| 变体 | 训练侧改动 | framework val（best） |
|---|---|---|
| `tri_final` | 主体 lr 1e-6（近冻结）+ aux 5e-3 | 0.5660 |
| `tri_final2` | backbone 5e-6 / enc+dec 3e-5（半解冻） | 0.5673 |
| `tri_final3` | 同 final2，seed/轮数不同 | **0.5675** |
| `tri_bold` | 解冻 + 16 epoch | 0.5674 |
| **RGB seed1 基线** | — | **0.5660** |

**配对 Δ ≈ 0，且四种策略（近冻结 / 半解冻 / 全解冻 / 不同 seed）结果一致** ——
这不是"配置没调好"，是**机制层面没有产生可用的新增信息**。

### 三条最硬的证据

1. **通道消融：置零无影响**

   | 输入 | mAP（val300 口径 B） |
   |---|---|
   | 完整 5 通道 @800+928 | 0.5678 |
   | IR 置 0 | 0.5678 |
   | Depth 置 0 | 0.5678 |
   | 完整 5 通道 @800+1024+1088 | 0.5778 |
   | **Depth 置 0 @800+1024+1088** | **0.5777** |

2. **融合层权重几乎没动**（tri_final3 实测）
   ```
   fuse.{0,1,2}.proj.weight  std = 0.0018 / 0.0021 / 0.0021   （初始化精确为 0）
   fuse.{0,1,2}.gate.1.bias  mean = 0.992                      （初始化 1.0）
   ```
   残差注入强度约 0.2%~2%，不足以改变 top-100 框的选择。

3. **所有增益都来自推理尺度，没有一分来自融合**
   APs 0.3053 → **0.3365（+3.12pp）**，全部由 800+928 → 800+1024+1088 带来。
   而训练尺度带上限是 **992** —— 模型从没在它实际被使用的尺度上训练过。

> ⚠️ 更正一条外部情报：**"depth 73% 像素为 0" 不成立**。实测 60 张：
> `TRAIN tri/depth zero=27.8%`、`TEST depth zero=28.1%`。73% 那个数字只对
> 测试集里那 117 张 640×360 的 `.jpg` depth 成立（子集约 77%）。
> 因此"depth 是纯噪声、应该丢掉"的结论**证据不足**；MCF-Net 在本赛题数据上实测
> Depth 单模态 mAP50=35.39、RGB+Depth=63.13 vs RGB 60.63 —— **depth 有信息，是我们没接上**。

## 1. 三条根因（第一性，决定改什么）

### R1 尺度饥饿（最确定）
训练带 `generate_scales(800, repeat=4)` = **576~992**；实测最优推理尺度是 **1088**，
已经越出训练带上限。⇒ 模型在"外推"状态下工作。

### R2 融合支路缺乏学习压力
融合残差从**精确 0** 起步（零初始化，A2DINOv3/ControlNet 的标准做法，本身没错），
但它唯一的梯度来源是"检测 loss 经由近零残差回传"。
实测结果是**梯度方向长期不一致**（Adam 下 14 epoch 只走到 std 0.002），
说明**没有稳定可用的判别信号**——而不是"梯度为 0"。
我们试过解冻主分支（final2/final3/bold）来增强这个信号，**已证伪**。

### R3 辅助模态预处理未对齐
- depth：线性 `/80`，20.4m 以上饱和、8cm 步长；工业标准是 **log 深度**
  （Ultralytics 官方深度头就是 log 空间，δ1 0.221→0.367，+66%）
- IR：无对比度增强。参考队伍 Woody611 用 **CLAHE**
- 两者都**没有自己的 mean/std**，与 RGB 共用归一化
- depth 通道的 padding 用 0 —— 而 0 是合法近场值，会让模型在图像边缘学到**虚假的深度梯度**
  （Woody611 实测：必须用 114 当"忽略"哨兵）

## 2. 架构升级（四级，按 EV 排序）

### L1 —— 训练分辨率对齐到 1024 【最高性价比，改动最小】

```yaml
# configs/seed1_1024.yml（基于 seed1_800.yml）
eval_spatial_size: [1024, 1024]
train_dataloader:
  dataset:
    transforms:
      ops:
        - {type: Resize, size: [1024, 1024]}
  collate_fn:
    base_size: 1024          # ← 训练带变成 736~1264
    base_size_repeat: 4
epochs: 16
optimizer:
  lr: 0.0001                 # 热启动微调，比从头训的 2.5e-4 低
```

**理由**：把 1024/1088 推理从"外推"变成"内插"。今晚的证据链最完整。
**代价**：显存 ×1.6，每 epoch 从 2min → 3.5min（4 卡 bs16）。
**参考**：AIC2026 Track6 论文《Frozen High-Resolution Inference for Cross-City Detection》
704→1120 冻结推理 = **+3.82 AP**，小目标收益最大；Track6 冠军 RF-DETR-HR 用 2200×2200。

### L2 —— 加 P2 检测头（小目标专用）【收益潜力最大】

D-FINE 现在只有 P3/P4/P5。加 stride-4 的 P2：

```yaml
HGNetv2:
  return_idx: [0, 1, 2, 3]          # 从 [1,2,3] 改成 4 级

HybridEncoder:
  # ★ 已核实：HGNetv2-B4 的 stage 输出通道数是
  #   stage1 128 (stride 4) / stage2 512 (8) / stage3 1024 (16) / stage4 2048 (32)
  #   来源：src/nn/backbone/hgnetv2.py 第 402-410 行 arch 字典
  #   现有 return_idx [1,2,3] + in_channels [512,1024,2048] 与此完全吻合
  #   ⇒ 加 P2 后应写 [128, 512, 1024, 2048]，**不是 256**（填错必崩）
  in_channels: [128, 512, 1024, 2048]
  feat_strides: [4, 8, 16, 32]
  use_encoder_idx: [3]              # 在最高层做 AIFI
  num_encoder_layers: 1

DFINETransformer:
  num_levels: 4
  feat_strides: [4, 8, 16, 32]
  num_points: [3, 6, 3, 3]          # 原来是 [3,6,3]，末尾补一项
```

**代价**：显存 +~20%，推理 -15%。
**理由**：我们 APs=0.28~0.34 而 APl=0.73，是典型的小目标短板；
PDP-RTDETR 加 P2 后小目标 mAP **+11.2%**。
**注意**：L1（高分辨率）与 L2（P2 头）是**同一机制的两条路**（都让目标在特征图上变大），
**先做 L1 看效果，再决定要不要 L2**，不要同时上（无法归因）。

### L3 —— 融合机制重做（真正的"更好的三模态"）

三条候选，按改动量从小到大：

**(c) 辅助监督头**（改动最小，机制最直接）
给 aux 支路的特征 `a3/a4/a5` 各接一个**共享的轻量检测头**（或复用主干检测头的浅层），
对同一批 GT 做辅助检测损失。这样 aux 支路**有了自己的梯度来源**，
绕开"loss 经由近零残差回传"这个死结。
```python
# tri_dfine.py 里加
self.aux_head = DFINELayer(...)   # 轻量，与主头共享权重或独立
# forward 里
aux_outputs = self.aux_head(a3, a4, a5)
# 总损失 = 主损失 + λ * 辅助检测损失（λ 建议 0.3，后期衰减到 0）
```

**(b) 低秩通信瓶颈 + 稀疏交互（A2DINOv3, arXiv 2608.21099）**
```
现状: f' = f + ZeroConv(a) · 2σ(Gate(a))          # 全秩 1x1 conv
改成: f' = f + W_up(W_down(a)) · 2σ(Gate(a))      # W_down: C→r, W_up: r→C, r=64~128
```
A2DINOv3 用零初始化 up-projection + 低秩瓶颈 + 只在稀疏层 {5,8,11} 交互，
在四个多模态检测榜上是 SOTA；零初始化 43.05 vs 随机初始化 42.43。

**(a) 双 backbone（LiteFusion-DETR, ICPR 2026 —— 与我们最接近的公开工作）**
第二条 HGNetv2 专门吃 `[IR|Depth]`，在 S3/S4/S5 与 RGB 分支融合
（高层用 PCMGT、低层用 DBAF）。改动最大，但这是唯一"从结构上保证辅助模态
有独立表征通路"的方案。第二条 backbone 可用 seed1 的 RGB 预训练权重
**按通道复制**初始化（IR/Depth 复制 RGB 通道均值或三通道均值）。

### L4 —— 预处理对齐（与 L1/L3 正交，可并行）

```python
# depth（替换现在的 /80）
d16 = np.asarray(Image.open(p))          # uint16 毫米
if d16.dtype == np.uint16:
    d = np.log1p(d16.astype(np.float32)) / np.log1p(20000.0)   # 覆盖 0~20m
else:
    d = d16.astype(np.float32) / 255.0                          # 已是 8bit 的那批
d = (d * 255).astype(np.uint8)

# IR（替换现在的直接 /255）
ir = np.asarray(Image.open(p).convert('L'))
lo, hi = np.percentile(ir, 1), np.percentile(ir, 99)
ir = np.clip((ir - lo) / max(hi - lo, 1e-6), 0, 1)
ir = (clahe(ir, clip_limit=2.0) * 255).astype(np.uint8)

# padding 哨兵（训练与推理都要改）
# RandomZoomOut(fill=0) 与 collate padding 对 depth 通道应填 114，而不是 0
```

## 3. 训练策略（与架构改动配套）

1. **按序列切分验证集**，扩到 500+ 张。现在 val300 标准误 ±1.6pp，
   盖过一切真实收益——这是所有调参的前提。
2. **模态 dropout**：训练时以 30% 概率把 IR 或 Depth 整通道置 0，
   强迫模型学"缺模态回退"。这是让融合真正产生增量的关键机制。
3. **两阶段**：前 3 epoch 冻结 base 暖机 → 解冻 base（lr 为基线的 1/10）。
   注意：今晚的"只解冻不暖机"已证伪，所以暖机阶段必须保留。
4. **步数预算对齐基线**：不要再用 batch 16 把步数压到基线的 8%。

## 4. 明日执行顺序（GPU 0-3 串行，GPU 4-7 并行）

| 顺序 | 实验 | 时长 | 判据 |
|---|---|---|---|
| 1 | L1：1024 热启动微调（seed1 → 1024） | ~1.5h | framework val > 0.5660 且 APs 上升 |
| 2 | L4：预处理对齐（log-depth + IR CLAHE + padding 哨兵）+ 单模态基线 M2/M3 | ~2h | 先量出 IR/Depth 各自的单模态上界 |
| 3 | L3(c)：辅助监督头（在 L1 的基础上） | ~2h | 通道消融不再"置零无影响"即算成功 |
| 4 | L2：P2 头（若 L1 未吃掉小目标收益） | ~2h | APs 显著上升且 APl 不掉 |
| 5 | L3(a)：双 backbone（若前面都不够） | 半天 | — |

**判据统一**：所有实验必须在**同协议**下与 seed1 比较，并用**按序列聚类的 bootstrap**
给出 Δ 的置信区间；点估计落在 ±1.6pp 内的一律视为"无结论"。

## 4.5 一条被 WorkBuddy 指出、比"单模态基线"更 decis 的验证实验

我原方案里想用"IR-only / Depth-only 单模态基线"回答"辅助模态到底有没有信息"。
**WorkBuddy 指出这不够**，理由是：

> **IR 的价值可能是稀疏的——只在暗光/夜间样本上大。** 在 300 张全量上平均，
> 一个只在 20% 样本上 +5pp 的增益会被稀释成 +1pp，再被 ±1.6pp 噪声吃掉。
> **平均为 0 ≠ 处处为 0。**

所以我们观测到的"门控 Δ ≈ 0"是**全局抵消**，不代表局部无效。

**更便宜的 decisive 实验（零训练，1 小时可出）：**
用现有 `tri_final/best_stg1.pth`，在 val300 上按 **RGB 平均亮度分四分位**，
**在每个分层内**分别做「模态置零 vs 完整」的配对 Δ：

- 若**最暗四分位**的 Δ 显著 > 0（方向稳定、折半为正）⇒ IR 有真实增量信息，
  值得投 L3，且应该做**条件式融合**（门控按亮度/置信度自适应），而不是全局融合
- 若**连最暗四分位**都 ≈ 0 ⇒ IR 在本数据集确实没用，**L3 整层砍掉**，
  GPU 全投 L1/L2，并把这条阴性结论写进报告

**结论**：明日执行顺序里，"亮度分层配对 Δ" 应排在 "单模态基线" 之前。

### 另一条核实结果

WorkBuddy 建议先查 `output/seed1_1024/`（DSH 18:50 硬停的那轮）是否已给出 L1 的初步答案。
**实测：该轮只跑到 epoch 0 就被终止**（`best_stat: {'epoch': 0, 'coco_eval_bbox': 0.5632}`，
日志最后一行是 `Epoch: [1/12]`），**没有可用的结论，L1 必须重跑**。
