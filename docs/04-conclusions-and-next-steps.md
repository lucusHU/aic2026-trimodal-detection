## 二、我们自己的实测证据（本次全部为真机跑出，非推测）

### 2.1 恒等性成立（此前的「起点掉 2.8pp」是误报）

| 运行 | 命令差异 | mAP |
|---|---|---|
| A | `-r tri_init.pth`（默认 aux → 5 通道，走 tri 分支） | **0.5641** |
| B | 同上 + 空 `--aux`（`nargs='*'` → 空列表 → 3 通道 RGB 回退分支） | **0.5641** |

两者严格相等；`fuse.*.proj.weight/bias` absmax **精确为 0** ⇒ 第 0 步与 RGB 模型数学等价。
此前拿 0.5361 vs 0.5641 论证"起点掉 2.8pp"，是因为 `--aux` 传空导致两条**不同的输入路径**，该对比无效。

### 2.2 通道消融（零训练成本，配对比较）

同一权重 `output/tri_final/best_stg1.pth`、同一批 val300、同一口径（800+928, nms0.7, md100）：

| 输入 | mAP@0.5:0.95 |
|---|---|
| 完整 5 通道 | **0.5678** |
| 红外通道置 0 | **0.5678** |
| 深度通道置 0 | **0.5678** |

### 2.3 与 seed1 的同口径对照

| 模型 | 口径 B（800+928, nms0.7, md100） |
|---|---|
| seed1（RGB 单模态） | 0.5670 |
| tri（三模态嫁接） | 0.5678 |

差 +0.0008 —— 落在 val300 的 ±1.6pp 噪声内。**三模态嫁接目前没有产生可测量收益。**

### 2.4 ⚠️ 一个必须写进报告的限定条件（WorkBuddy 提出，我认同）

消融"三通道置 0 结果完全相同"**只能证明输出未变，不能直接证明"模态无用"**。原因：

1. `2σ(gate_bias=0.028) ≈ 1.014` ⇒ 门是**全开**的（中性），残差就等于 `ZeroConv(a)` 本身；
   但我们**没有测** `‖ZeroConv(a)‖ / ‖f‖` 这个比值。若它 < 0.5%，那就是"信号没被有效注入"，
   而不是"信号没用"。aux 分支 lr 从 0 起步只跑了 24 epoch，很可能还在爬升。
2. 更可疑的真凶是**深度量化口径**：`16bit 毫米 /80 → clip(0,255)`，8cm 一步、20.4m 截断，
   且训练集里还有 149 张原本 uint8 未换算。城市深度严重长尾，这套线性量化可能把有效动态范围
   压成几个灰度级。**"门开大反而 −2.6pp"正是"喂了垃圾特征"的典型特征**——
   有用特征不会一放大就掉分。

⇒ **下阶段第一件要动的事是深度编码（`log1p(mm)/log1p(20000)` 或分位数归一化），而不是先怪模态。**

### 2.5 深度/红外的真实格式（推理链路上的致命坑，已解决）

测试集深度是**混合格式**，直接用会让辅助通道完全 OOD 且不报错：

| | 数量 | 格式 | 正确做法 |
|---|---|---|---|
| `.png` | 883 | `I;16` uint16，0~19999 毫米 | **必须 /80** |
| `.jpg` | 117 | RGB uint8，0~255（已量化） | 直接用 |

红外 1000 张均为 3 通道（数值相同），取第 0 通道。

### 2.6 排除了最后一个"输入侧 bug"假设

逐通道统计（各 150 张）：

```
TRAIN visible   R/G/B = 110.4 / 115.2 / 112.2   std 56.3 / 58.1 / 58.7
VAL   visible          107.6 / 113.3 / 109.6
TEST  visible(复赛)    107.9 / 114.0 / 110.2
TEST  visible(初赛)    110.6 / 115.9 / 111.9
```

**完全同分布，无通道错序、无 gamma 偏移。**
⇒ 线上 50 vs 本地 56.7 的落差是**真实泛化差距**，不是推理脚本能修的 bug。

## 四、下阶段方案（按性价比排序，这是今晚真正的产出）

### 第 0 步：重建可信验证集（最高优先级，其它一切的前提）

现状 val300 的 mAP 标准误 ±1.6pp（序列已见 0.5509 vs 序列未见 0.6345，差 8.4pp），
**盖过了所有真实收益**。今晚所有判断都卡在这里。

做法：按**序列**（而非随机帧）切分 train 2000，扩到 500+ 张验证；并对每个结论做
**paired bootstrap** 给出 Δ 的置信区间，而不是只报点估计。

### 第 1 步：修深度编码

- `log1p(mm)/log1p(20000)` 或分位数归一化，替代当前 `/80` 线性量化
- 统一那 149 张 uint8 的口径
- **depth 通道的 padding 用 114 而不是 0**（Woody611 实测：0 是合法近场值，
  用 0 padding 会让模型在图像边缘学到虚假的深度梯度）；`RandomZoomOut(fill=0)` 同理

### 第 2 步：逐模态单模态基线（先量出谁有用，再决定融合谁）

| ID | 模态 | 目的 |
|---|---|---|
| M1 | RGB | 上界基线 |
| M2 | IR（含 CLAHE 与不做处理两版） | IR 到底有没有信息 |
| M3 | Depth | Woodry611 的矩阵显示 RGB+Depth(4ch)=0.51955 > RGB+IR+Depth(5ch)=0.515281，IR 很可能是负资产 |
| M4/M5 | RGB+IR / RGB+Depth | 分离贡献 |

### 第 3 步：联合训练，而不是嫁接

今晚的机制解释：**24 epoch 里 base lr=1e-6 等于全程冻结，aux 学出来的东西 base 根本没机会适配它。**
门开大 → 注入噪声（−2.6pp）；门关小 → 完全惰性（0 贡献）。**没有中间地带。**

正确配方：
1. 从 obj365 预训练权重出发；
2. 前 2–3 epoch 冻结暖机，**之后 base 解冻**（用基线 lr 的 1/10）；
3. 训练期做**模态 dropout**（随机把 IR 或 Depth 整通道置 0）——这是唯一能强迫模型
   学会"缺失模态下的回退"、从而让融合真正产生增量的机制；
4. 步数预算对齐基线（≥1/3），不要用 batch 16 把步数压到基线的 8%。

### 第 4 步：可借鉴的模块（按优先级）

1. **GM-DETR 的高效融合编码器**（DETR 系、可见光-红外）—— 需等代码或自行按论文实现
2. **MM-DETR 的频域模态适配器 + Mamba 双粒度融合**（RT-DETR 系）—— 代码未放出
3. **FreDFT 的频域融合 Transformer**（IEEE TMM 2026）
4. **SFEDet 的稀疏融合 + 滚动卷积**（CSDN 实测 24.5M 参数优于 288M 的 Fu-Mamba）
5. **MDQF 的查询融合 + 模态解剖**（哈工大深圳，面向模态不平衡）
